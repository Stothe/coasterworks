# Plan C: UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The park UI Steve chose: a bottom dock of labeled tools with a tray, one right-side inspector, status pills, a ⌘K command bar, right-click actions, toasts and a timeline, all driven by the sim's command catalog so Plan D's rides and guests plug in as data.

**Architecture:** The host exposes the sim's catalog through a new `catalog_list` query. The web app builds one client-side action registry from it (plus UI-only actions like pause and classic view); the dock, tray, command bar, context menu and inspector are all views over that registry. Commands whose input is a map rectangle become placement tools (the existing brush); other commands get a schema-driven form. Selection (a tile today, an entity in Plan D) drives the inspector. Components stay in `apps/web/src/ui` on a small panel kit (Radix primitives + the glass tokens).

**Tech Stack:** React 19, Tailwind 4, Radix UI primitives (`@radix-ui/react-dialog`, `-tabs`, `-dropdown-menu`, `-context-menu`, `-tooltip`), `cmdk` for the command palette, Zod JSON Schema from the sim catalog, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-16-coasterworks-design.md` (sections 4.4, 5.3 "one action list", 6.1 "agent actions appear in the timeline").

**Spec refinements made here:**
- `packages/ui` (spec 5.2) is deferred: components live in `apps/web/src/ui` until a second app needs them. The panel kit is written so it can be lifted out later.
- Dock tools are present from the start even when their trays are empty (Paths, Rides, Scenery, Shops, Staff show an empty state until Plan D), so the layout is final and Plan D only adds data.
- The inspector's entity kinds in this plan: the park and a tile. Rides, guests and staff kinds arrive with Plan D.

- No new network calls; the catalog is fetched once per connection.

## Review Focus

1. A command whose JSON schema the generic form cannot render (nested object, array, unknown type) must show "This action needs the full UI" and not crash the command bar. Test in Task 2.
2. Running a placement command from the command bar while another tool is active must switch tools cleanly and `Esc` must return to Select with no dangling highlight. Test in Task 3 (unit) and Task 6 (e2e).
3. The inspector must not keep a stale selection after the selected thing changes under it (an agent lowers the selected tile); it re-renders from the latest snapshot. Test in Task 4.
4. The timeline must show agent actions with their client badge and must not duplicate entries when a snapshot and an event arrive for the same log id. Test in Task 5.
5. Shortcut keys must not fire while typing in the command bar or a loan amount field. Test in Task 2 and Task 4.

### Task 1: Catalog query, action registry, panel kit

**Files:**
- Create: `packages/sim/src/queries/catalog.ts` (`catalog_list {}` → `CatalogEntry[]`), modify `packages/sim/src/registry-default.ts`, `packages/sim/test/queries.test.ts`
- Create: `apps/web/src/actions/types.ts`, `apps/web/src/actions/registry.ts`, `apps/web/src/actions/schema.ts`, `apps/web/src/actions/useActions.ts`
- Create: `apps/web/src/ui/kit/{Panel,Tabs,Segmented,IconButton,Field,Kbd,EmptyState}.tsx`, `apps/web/src/ui/kit/index.ts`
- Test: `apps/web/test/actions.test.ts`, `apps/web/test/schema.test.ts`, `apps/web/test/kit.test.tsx`

**Interfaces:**
- `catalog_list` returns the registry's `CatalogEntry[]` (`{ name, description, category, inputSchema, undoable, kind }`), category `"sim"`.
- `apps/web/src/actions/types.ts`:
  ```ts
  export type ActionKind = "command" | "query" | "ui";
  export interface Action { id: string; title: string; description: string; category: Category | "ui"; kind: ActionKind; keywords: string[]; shortcut?: string; placement?: "rect" | "tile"; schema?: JsonSchemaObject; run: (ctx: ActionContext, input?: unknown) => Promise<void> | void; enabled?: (ctx: ActionContext) => boolean }
  export interface ActionContext { client: SimClient; snapshot: DecodedSnapshot | null; ui: UiStore /* tool, selection, inspector, speed helpers */ }
  ```
- `registry.ts`: `buildActions(catalog: CatalogEntry[], ui: UiActionDeps): Action[]` where commands with a schema containing integer `x, y, w, h` get `placement: "rect"` and `run` sets the active placement tool with the command name and non-rect defaults; other commands get `run` that opens the form (Task 2) or executes directly when the schema has no properties; queries are excluded from the command bar except `park_status`-style "Show" actions (none for now); UI actions: `ui.pause`, `ui.speed.1|2|4|8`, `ui.undo`, `ui.redo`, `ui.classicView`, `ui.tool.<dock tool>`, `ui.inspector.park`, `ui.help`. Titles: humanize `terrain_set_water` → "Set water"; descriptions from the catalog. `shortcut` strings like `"⌘Z"`, `"1"`.
- `schema.ts`: `fieldsFor(schema: JsonSchemaObject): FormField[] | null` returning `null` when any property is not a supported primitive (`integer`/`number` with optional min/max/default, `boolean`, `string` with optional enum, and `enum` of numbers); `isRectSchema(schema)`.
- `useActions(): { actions: Action[]; byId: Map<string, Action>; ready: boolean }` fetching `catalog_list` once when the client is ready.
- Kit: `Panel` (glass container with optional header/footer), `Tabs` (Radix), `Segmented` (role group + `aria-pressed`), `IconButton` (32 px min, `aria-label`, Radix tooltip), `Field` (label + control + hint/error), `Kbd`, `EmptyState` (icon, title, hint).

- [ ] **Step 1: Sim test**: `catalog_list` returns every registered command and query with `kind` and a JSON schema; register and run it.
- [ ] **Step 2: Web tests**: `buildActions` marks `terrain_raise` as placement rect and `finance_take_loan` as a form action with one integer field (min 100, max 5_000_000); `fieldsFor` returns null for a nested object schema (Review Focus 1); kit components render with the right roles and the `aria-pressed` state.
- [ ] **Step 3: Implement; run; PASS. Commit** `feat(web): catalog query, client action registry, panel kit`.

**Files:**
- Create: `apps/web/src/ui/CommandBar.tsx`, `apps/web/src/ui/ActionForm.tsx`, `apps/web/src/state/uiStore.ts` (Zustand: `tool`, `placement`, `selection`, `inspector`, `commandBarOpen`, `formAction`)

- Test: `apps/web/test/CommandBar.test.tsx`, `apps/web/test/ActionForm.test.tsx`, `apps/web/test/uiStore.test.ts`

**Interfaces:**
- `CommandBar`: `cmdk` dialog opened by `Cmd/Ctrl+K` (and the search icon top-right); groups by category (Terrain, Finance, Park, View, Speed, History); fuzzy filter on title + keywords; `Enter` runs the action; placement actions close the bar and set the tool with a hint toast "Click the map to place; Esc to cancel"; form actions open `ActionForm` inline below the list; unsupported schemas render the "needs the full UI" notice (Review Focus 1). - `ActionForm`: renders `fieldsFor(schema)` with `Field`s, validates with the JSON schema bounds client-side, submits via `client.command(name, input)`; shows the `ExecResult` error inline; money fields display dollars and submit cents.
- `uiStore`: `tool: DockTool | "select"`, `placement: { command: string; defaults: Record<string, unknown>; size: 1|2|3 } | null`, `selection: { kind: "tile"; x; y } | { kind: "park" } | null`, `inspectorOpen`, `commandBarOpen`, `formAction: Action | null`; actions `setTool`, `startPlacement`, `cancel()` (Esc: clears placement and form, returns tool to Select, keeps selection).
- `keys.ts`: central keymap `{ "mod+k": openCommandBar, "mod+z": undo, "mod+shift+z": redo, "escape": cancel, "1".."7": dock tools, "space": pause, "+"/"-": speed, "?": help, "home": classic }` with the typing guard (Review Focus 5).
